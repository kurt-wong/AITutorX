## 14.1 Root Cause

修改前 `boundary.py` 的判定语句：

```python
_INTERFACE_IDENTITY_VERSIONS = {2, "2"}          # boundary.py:76

if identity_version not in _INTERFACE_IDENTITY_VERSIONS:   # boundary.py:220
    raise BoundaryViolation(CODE_OUT_OF_SCOPE_IDENTITY_VERSION, ...)
```

`x in <set>` 的成员判定**必须**先求 `hash(x)`。对 unhashable 取值 CPython 抛的是
`TypeError`，而**不是**返回 `False`：

| `identity_version` | `hash(x)` | `x in {2, "2"}` 实际结果 |
| --- | --- | --- |
| `[]` / `{}` / `set()` / `bytearray()` | `TypeError: unhashable type` | **异常上抛** |
| `2` / `"2"` / `2.0` | 正常 | `True` |
| `1` / `3` / `"1"` / `"3"` / `True` / `False` | 正常 | `False` |

而 `enforce_interface_scope()`（`boundary.py:281-289`）的异常边界是：

```python
try:
    identity = normalize_interface_identity(source_content_sha256, identity_version)
except BoundaryViolation as exc:      # ← 只捕获 BoundaryViolation
    return InterfaceScopeDecision(accepted=False, code=exc.code, ...)
```

`TypeError` **不是** `BoundaryViolation` 的子类，因此：

```
identity_version = []
  ↓ normalize_interface_identity
  ↓ identity_version not in {2, "2"}   →  TypeError: unhashable type: 'list'
  ↓ 未被 except BoundaryViolation 捕获
  ↓ 穿透 enforce_interface_scope 的决策层
  ↓ runner_b2.run_corpus:525 / runner.py:262（两处都在无 try 的位置）
  ↓ 整个 for 循环中断 → run_corpus() 异常中止 → 报告文件根本不写出
```

**输入如何抵达边界**：`manifest_reader.load_manifest`（`manifest_reader.py:122`）对
`identity_version` 做 `raw.get("identity_version")` **verbatim 透传、零类型校验**
（`Manifest.identity_version: int | str | None` 仅为注解，Python 不做运行时约束）。
故 JSON 里写 `"identity_version": []` 会原样抵达判定语句。

**为什么 M1–M5 拦不住**：`read_manifest_identity` / `load_raw_bytes_identity` /
`read_ir_identity` / `verify_identity` / `evaluate_identity_gate` 四个冻结模块
**都不读取、不判定** `identity_version`（只管 `source_content_sha256` 身份真实性），
属另一正交轴。F-INT-08 已把 `identity_version == 2` 接入边界，但那次修正只覆盖了
**取值**域，未覆盖**类型/形态**域——本 Finding 是形态域的残余缺口。

## 14.2 Fix

**修在哪里**：`backend/scripts/preprocessing_consumer/boundary.py` —— 且**只**修在这里。

**怎么修**：在唯一权威 `normalize_interface_identity()` 内、于 set 成员判定**之前**，
加一道**显式确定性类型白名单**；不合格输入转成 `BoundaryViolation`，而不是让 Python
类型错误外泄。

```python
# boundary.py（新增常量）
_IDENTITY_VERSION_ACCEPTED_TYPES: tuple[type, ...] = (bool, int, float, str)

# boundary.py（normalize_interface_identity 内，位于成员判定之前）
if not isinstance(identity_version, _IDENTITY_VERSION_ACCEPTED_TYPES):
    raise BoundaryViolation(
        CODE_MALFORMED_IDENTITY_VERSION,
        f"identity_version must be a JSON scalar (bool/int/float/str), got "
        f"{type(identity_version).__name__} value {identity_version!r}; no "
        f"coercion is permitted (list/dict/set are rejected as malformed — "
        f"never stringified, never defaulted to 2).",
    )
if identity_version not in _INTERFACE_IDENTITY_VERSIONS:
    ...
```

新增稳定错误码 `CODE_MALFORMED_IDENTITY_VERSION = "MALFORMED_IDENTITY_VERSION"`
（按 `boundary.py:94` 既有规则「新增须登记；不得改语义复用旧码」登记于 `__all__`）。
**未**复用 `MALFORMED_IDENTITY`（那是 `source_content_sha256` 的格式码，语义不同）。

**为什么不会建立第二套 scope rule**：

1. 判定规则（`{2, "2"}` 成员判定）**一处未改**——只是在其**前面**加了形态闸门。
2. 新增判定**全部在 `normalize_interface_identity()` 内**；`enforce_interface_scope()`
   仍是 100% 委托 + 决策形状适配，其 `except BoundaryViolation` **保持不变**。
3. `runner.py` / `runner_b2.py` **零改动**（本轮 AITutors-v3 提交只含 `boundary.py` +
   1 个新测试文件）。两个 runner 不自行判定 `identity_version`。
   由 `TestSingleAuthorityPreserved` 用 **AST** 断言锁死：两个 runner 模块内不存在任何
   对 `identity_version` 的 `ast.Compare`；`_INTERFACE_IDENTITY_VERSIONS` 与
   `_IDENTITY_VERSION_ACCEPTED_TYPES` 只出现在 `boundary.py`。
4. `normalize_interface_identity(` 的生产调用点仍**恰好 1 处**（`enforce_interface_scope` 内）。

**为什么不采用 `except TypeError`**（任务 §4.2）：宽泛捕获会把真正的程序错误（如
`hash()` 实现缺陷、错误的比较运算）一并「当成 scope rejection」吞掉。显式类型闸门
把失败**定位到输入形态**，错误码可断言、可审计，其余异常照常上抛。

**fail-closed 保证**（§4.3）：拒绝路径**不产出** `NormalizedIdentity`（`identity is None`），
**不**做任何隐式转换——`[]` 不会变成 `"[]"`，`{}` 不会变成 `"{}"`，更不会变成 `2`。
Producer 声明值在 runner 拒绝记录中 verbatim 保留（`declared_identity_version`），
不解释、不改写。
