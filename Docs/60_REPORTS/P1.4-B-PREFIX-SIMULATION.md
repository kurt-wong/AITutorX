## 0. 结论摘要（TL;DR）

任务指令第 3 节要求「不得预设 `B=3 → auto +3`，必须以实际 Gate replay/simulation 证明收益」。
模拟已完成，结论比预期更重要：

| 样本 | 现状 | 补 D 后语法 | Gate 决策变化 | 收益 |
|------|------|-------------|---------------|------|
| **化学 Q23** | `answer=D`，labels `[A,B,C]` | `None → True` | `pending_review → auto_approve` | **+1 auto** |
| **历史 Q29** | `answer=C`，labels `[A,B,C]` | `True → True` | `auto_approve → auto_approve` | **0** |
| **数学 Q4** | answer 是解析 blob | `None → None` | `pending_review → pending_review` | **0** |

**B 修复的真实收益 = 1 个 auto（不是 3 个）。** 三样本 other layers（structural/provenance/
semantic）实测均为 `pass`，故 binding constraint 只在 grammar 一层 —— 见 §3.5。

同时发现一个**收益大一个数量级的相邻问题**，但它落在本任务的 STOP CONDITION 之内：

| 问题 | 归属 | 潜在 auto 收益 | 本任务可否处理 |
|------|------|----------------|----------------|
| 数学卷 25 个单选的 answer 切片取到整块解析 | answer-slice granularity | **+25（上界）** | **否 — STOP CONDITION #5/#6 区** |
| 化学 Q23 第四项 label 丢失 | option-label parsing compat | +1 | 是（唯一可动项） |

## 1. Gate 判定机制（决定性事实）

`app/domains/gate/grammar.py::verify()`（AnswerTokenContract，BUG-V3-044 冻结）：

```python
if canonical_type == "single_choice":
    letter = _answer_form_single_choice(cleaned)
    if letter is None:
        return None            # → policy.py 记为 auto_blocker → pending_review
    return True if letter in labels else None
```

要点：**单选 auto 的充分必要条件是「答案字母 ∈ 已解析 option labels」**。
因此「补出一个 option label」只在**答案字母原本不在 labels 里**时才产生 auto 收益。

- Q23：`D ∉ [A,B,C]` → 补 D 使其成立 → **翻 auto**
- Q29：`C ∈ [A,B,C]` 已经成立 → 补 D 不改变结果 → **不翻**
- Q4：answer 不是可表达 token → 语法本来就是 `None`，补 D 后仍是 `None` → **不翻**

`policy.py` 另有两个独立 auto_blocker，与 option 无关：
1. `not byte-proven (resolution not in {exact, normalized})`
2. `leaf answer not source_located+complete`

## 2. 数学 Q4 的真实阻塞原因（与 option label 无关）

数学 manifest 的 Q4 声明：

```json
"answer_lines": [234, 240],   // 7 行
"options_lines": [21, 23],
"options": [A, B, C]
```

`answer_lines` 覆盖的是**整块解析**（【考点】/【分析】/【解答】…故选：A.），
编译器如实切片 → `answer.text` 是一个 96 字符的解析 blob → 语法无法表达 → `None`。

**关键判别实验**（`_p14b_answer_block_shape.py`，全语料 214 个 choice unit）：

```text
single-line answer span : 188   （化学25 历史50 地理20 政治27 物理14 生物40 英语10 语文2）
multi-line  answer span :  26   （数学25 + 化学1）
token-exclusive line    :   0   ← 全语料没有任何一行的正文只有答案 token
token glued to prose    :  25   （全部是数学 故选：A. 形态）
no 故选/答案 token      : 189
```

**数学卷是唯一把整个解析块声明为 `answer_lines` 的卷种**，其余 8 卷全部声明单行。
26 个 multi-line span 中：**25 个恰好就是 pending_review 的答案 blob 单元**，第 26 个是化学 Q23（单行、干净 `D`）。

反事实上界（`_p14b_answer_slice_counterfactual.py`）：
25 个 blob 单元的解析块内**都**含终端 `故选：X`/`答案 X`，且 **X 全部 ∈ 已声明 labels**。
即「把 answer 切片收窄为终端答案语句」可解锁 **25 个 auto（上界）**。

---

## 3. 为什么不建议 MIMO 现在动这 25 个

这 25 个不是 option evidence 问题，而是 **answer slice / `answer_lines` 声明**问题：

- 若修改点在 Producer 的 `answer_lines` 生成（即 producer data / annotation）→ **禁止修改 Producer 数据**（AGENTS.md）
- 若修改点在 Resolver/Compiler 的 answer 切片选择 → 触及 **AnswerTokenContract / Resolver authority**（任务指令明确不许改）

并且证据显示这很可能是 **数学卷 annotation 的 `answer_lines` 声明缺陷**（其余 8 卷均单行），
属「source annotation 边界」类，应与已收口的 G1/G3 同类处理，而**不是**塞进 P1.4-B。

→ 建议：**记为 independent finding，另立案**；P1.4-B 若要扩大范围必须先取得裁决。

## 3.5 模拟方法修正（v2）— 权威预测模型

### 3.5.1 我方 v1 表格的一处自相矛盾（已修正）

v1 脚本用 `answer_letter = _clean_answer(text)[:1]` 取**原始答案文本的第一个字符**：

- 历史 Q29 `'29. 【答案】C'` → 取到 `'【'` → 表格打印 `answer ∈ old labels = False`
- 数学 Q4 解析 blob → 取到 `'4'` → 同样 `False`

但同一张表里 Q29 的 grammar 是 `True` —— **自相矛盾**。真实判定始终来自 `verify()` 自身的
`_answer_form_single_choice()`（它正确解析 `【答案】C` → `C`）。

**v2 修正**（`_p14b_v2_corrected.py`）：直接调用契约函数取字母，不再做 `[:1]` 切片。

| 样本 | 契约解析出的字母 | letter ∈ old | letter ∈ new | grammar old→new | 预测决策 |
|------|------------------|--------------|--------------|-----------------|----------|
| 化学 Q23 | `D` | False | **True** | `None → True` | `pending → auto` |
| 数学 Q4 | `None` | — | — | `None → None` | `pending → pending` |
| 历史 Q29 | `C` | **True** | True | `True → True` | `auto → auto` |

**v1 与 v2 的最终结论一致：B 修复 auto 增益 = +1。** 仅表格字段的因果解释被修正。

### 3.5.2 「注入假 span」是模拟伪影（确认 MIMO 判断）

v1 向 CompiledSnapshot 注入了一个复用 donor span 的假 option，使 `_role_spans` 出现
重复 span → provenance 报 `duplicate content span consumed across candidate leaves` → `rejected`。
`resolved.get(sid)` 能查到 donor span（所以不是 "span 不在 ResolvedRun"），
但**重复消费**仍触发矛盾判定。故 full `evaluate()` 的 `rejected` 是**模拟设计缺陷**，非真实结局。

**采纳的权威预测模型**：

```text
prediction = grammar(verify with recovered labels) AND other_layers_pass
```

真实修复应把**源中已存在的内容**（Q23 L194 / Q4 L23 / Q29 L307）绑成 exact ResolvedSpan，
不引入新 span、不重复消费。

### 3.5.3 三样本 other layers 实测

`_p14b_v2_corrected.py` 逐样本读取 `gate["layers"]`：

```text
化学/Q23  structural=pass  provenance=pass  semantic=pass  -> other_layers_pass=True
数学/Q4   structural=pass  provenance=pass  semantic=pass  -> other_layers_pass=True
历史/Q29  structural=pass  provenance=pass  semantic=pass  -> other_layers_pass=True
```

→ 三样本的 binding constraint **确实只在 grammar 一层**，MIMO 的 `other_layers_pass` 前提成立。

## 4. 化学 Q23 的收益前提是「它真的能进 auto」

> **重要限定（避免把 +1 读成天花板）**：本模型 `prediction = grammar AND other_layers_pass`
> 是 MIMO 采纳的权威预测。按**同一模型**，数学 Q4 一旦 answer-slice 修好
> （`letter=None → 'A'`，且 `A ∈ [A,B,C,D]`）→ `grammar → True` → **`pending → auto`**。
> 即：**B 修复单独看 = +1；但 Q4 的 grammar 已在同一个 pass 里被记为 `True`，
> 它的 `pending` 完全由 answer-slice 造成。** 两个修复合起来的上界是 **+26**（Q23 +1，数学 25）。
> 因此 +1 是「只做 Option-Label 修复」的收益，**不是**本类缺陷的全部可解锁量。

模拟结论（`_p14b_prefix_simulation.json`）：

```text
化学/Q23  leaf=Q23  type=single_choice
   answer text        : 'D'   (source_located=True complete=True resolution=exact)
   old option labels  : ['A','B','C']
   grammar old -> new : None -> True
   gate decision      : pending_review -> auto_approve
   current reasons    : ["leaf 'Q23' answer grammar: answer not expressible as canonical value"]
   simulated reasons  : ['strict-auto: all answers verified_correct=True']
```

这是**三个样本里唯一一个 option-set 是 binding constraint 的**。
所以 P1.4-B 的**全部可证明收益 = 1 auto**。

## 5. 全语料边界审计（回答「B 是否可泛化」的量化面）

`_p14b_mechanism.py` 交叉表（choice leaves = 183，root 决策：auto 154 / pending 68 / rejected 62）：

```text
decision x grammar:
   (auto_approve, grammar_True)   154
   (pending_review, grammar_None)  27
   (rejected, grammar_True)         2
```

27 个 pending 的构成：

| 形态 | 数量 | 性质 |
|------|------|------|
| answer = 单 token 且不在 labels | 2 | 化学 Q23（真 option-label 缺陷）+ 英语 Q5-6（C 内容源自始缺失） |
| answer = 解析 blob | 25 | 全部数学，**answer-slice 问题，非 option 问题** |

→ **B 类 option-label 的 pending 面只有 1 个真实可修单元 + 1 个内容源自始缺失（不可修）。**

## 6. 负样本面（negative tests 的原始素材）

`_p14b_false_positive_surface.py` 全语料扫描各候选规则：

| 规则 | 总命中 | 在 OPTIONS | 误报 | 结论 |
|------|--------|-----------|------|------|
| CLEAN（现产线） | 1317 | 696 | 621 | 现产线本就只在 slice 内使用，不能全语料套用 |
| **DIGIT_GLUE (`2D.`)** | **2** | **1** | **1** | 唯一真阳性 = 数学 Q4；误报 = 解析区 `2\cos^2a-1=2a)` |
| CHAR_GLUE | 90 | 8 | 82 | 太宽，不可用 |
| **SPACE_SEP (`D 麦哲伦`)** | **9** | **1** | **8** | 误报例：历史 L749 `B 是 1945 年…` 解析正文 |
| SPACE_SEP_LOOSE | 124 | 1 | 123 | 完全不可用 |

**硬约束**：任何 label 恢复规则必须
(a) 限定在 `options_lines` 声明范围内，
(b) 由 A./B./C. 平行序列 + 位置推出字母，
(c) 字母**不得**来自答案。
否则 DIGIT_GLUE 会把解析里的 `2a)` 认成 D，SPACE_SEP 会把解析正文 `B 是 1945 年` 认成 B 选项。

## 7. 对任务指令的两点修正建议

### 7.1 不变量表里的 `rejected = 5` 不是 Gate 不变量

read-only replay 结果：

| 作用域 | auto | pending | rejected | 合计 |
|--------|------|---------|----------|------|
| **leaf 作用域** | **154** | **68** | **5** | 227 |
| root 作用域 | 154 | 68 | 62 | 284 |

leaf 作用域与已接受基线**逐格一致**（227 = IR ready）。
root 的 `rejected=62` 里 **57 个就是 IR incomplete 的 root**（`semantic_status=incomplete` → structural fail → rejected），
剩下 5 个（历史 U51/U52/U53 无 stem + 地理 U16-17/U26-29 无 stem）与 leaf 的 rejected=5 对应。

→ 所以 `rejected=5` 是**定义在 IR ready 的 227 个 leaf 上**的；
一旦某个修复改变了 IR ready 集合，`rejected` 会**大幅跳变**（最多 +57）。
建议把不变量写全：`IR ready = 227`（leaf 作用域）与 `IR incomplete = 57`（root 作用域）**联合锁定**，
单独冻结 `rejected = 5` 会在 ready 集合变动时给出假警报。

### 7.2 第二阶段「共同解析规则」只有 1 个用户，不足以支撑泛化

三个样本中：
- 化学 Q23 = label **完全缺失**（B1）
- 数学 Q4 = `2D.` digit glue（B2）
- 历史 Q29 = `D 麦哲伦` space-sep（B2）

但**只有 Q23 因 label 而 pending**。Q29 本来就 auto（B 分类是审计发现，不是 Gate 缺陷），
Q4 的 Gate 阻塞与 label 无关。
因此「B 可泛化」在**证据普查层面**成立，但在**Gate 收益层面**不成立——
不要用 P1.4-B 的收益去论证共同规则的普适性。
