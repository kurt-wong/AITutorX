## 15.2 Root Cause — F-INT-01 与 F-INT-08 的关系

两者是**同一缺陷的两个侧面**，必须一并修正才成立：

```text
F-INT-01（结构性 / MEDIUM）
    helper 已实现  ≠  helper 已接入实际 runtime path
    `boundary.normalize_interface_identity()` 已实现且有单测，
    但**实际 runtime runner 从未调用它**，与 runner 的 M1–M5 链**不重叠**。
    → 边界校验体系没有「单一接入点」，呈现层（报告拓扑图）与执行层脱节。

F-INT-08（行为性 / MEDIUM）
    正因为 F-INT-01，Interface Scope 的 `identity_version` 字段口径
    （Frozen Contract §1.6：`identity_version == 2`）在常驻路径**未被强制**。
    M1–M5 只证明「文件身份真实性」（manifest 声明 SHA == raw bytes 实算 SHA），
    **不判定**「该输入是否属于 v0.2 Interface Scope」。
    → 理论输入：合法 SHA + 完整 identity + identity_version = 1 / 3
       仍可进入 V3 semantic/IR/Compiler/Gate pipeline。
```

**因果链**：F-INT-01 是**成因**（无接入点）；F-INT-08 是**后果**（口径未强制）。只修 F-INT-08 而不建立单一接入点，会退化为「又一处散落的检查」；只建接入点而不强制口径，F-INT-08 依旧成立。故本轮以「**单一权威接入点 + 该点强制 `identity_version == 2`**」一次解决两者。

**两轴正交性（重要）**：

| 轴 | 事实 | 负责组件 | 本轮 |
|---|---|---|---|
| Identity authenticity | manifest 声明 SHA == raw bytes 实算 SHA | M1–M5（冻结设计） | **未改动** |
| Interface Scope membership | `identity_version == 2` | `boundary.normalize_interface_identity` | **本轮接入 runtime** |

二者为 **AND**：任一拒绝即阻断。本轮**不复制** M1–M5，也**不在** M1–M5 内新增判定。

## 15.5 Behavior Matrix

经**真实 runtime 边界** `_verify_identity_boundary` 断言。矩阵用例构造原则：「valid identity」行必须让 M1–M5 **全部通过**（含匹配 resolver IR，使 `semantic=AVAILABLE`），否则会先因 `semantic_pending` 被 M5 阻断，证明的就不是本 Finding。

| Case | Expected | Actual | 证据 |
|---|---|---|---|
| valid identity + `identity_version=2` | **PASS** | `gate=PASS` / `identity=VERIFIED` / `semantic=AVAILABLE` / `accepted=True` | `test_valid_identity_and_version_2_passes` |
| valid identity + `identity_version="2"` | **PASS** | 同上 | `test_valid_identity_and_version_2_as_string_passes` |
| valid identity + `identity_version=1` | **FAIL** | `gate=BLOCK` / `identity=VERIFIED` / `semantic=AVAILABLE` / `code=OUT_OF_SCOPE_IDENTITY_VERSION` | `test_valid_identity_and_version_1_must_fail` ★核心 |
| valid identity + `identity_version=3` | **FAIL** | `gate=BLOCK` / `identity=VERIFIED` / `semantic=AVAILABLE` / `code=OUT_OF_SCOPE_IDENTITY_VERSION` | `test_valid_identity_and_version_3_must_fail` ★核心 |
| valid identity + missing version | **FAIL** | `gate=BLOCK` / `code=MISSING_IDENTITY_VERSION` | `test_valid_identity_and_missing_version_fails` |
| valid identity + `identity_version: null` | **FAIL** | `gate=BLOCK` / `code=MISSING_IDENTITY_VERSION` | `test_valid_identity_and_null_version_fails` |
| missing identity | **FAIL** | `gate=BLOCK` / `code=MISSING_IDENTITY` | `test_missing_identity_fails` |
| invalid SHA / identity mismatch | **FAIL** | `gate=BLOCK` / `identity=FAILED` | `test_identity_mismatch_fails` |
| malformed SHA | **FAIL** | `gate=BLOCK` / `reason=manifest_read_error: …` | `test_malformed_identity_fails` |
| malformed SHA（authority 直判） | **FAIL** | `code=MALFORMED_IDENTITY` | `test_malformed_identity_rejected_by_authority` |
| 越界版本 `0/1/3/4/-1/"1"/"3"/"v2"/"02"` | **FAIL** | 全部 `code=OUT_OF_SCOPE_IDENTITY_VERSION` | `test_any_out_of_scope_version_fails`（9 参数化） |

**不变量（任务书 §2）全部成立**：`2 → PASS`；`1 / 3 / missing / invalid → FAIL`。

**禁止模式的反证（`TestNoSilentCoercion`）**：

```text
version != 2  →  默认当成 v2         禁止 ✓  （authority 不产出 identity_version="2"，
                                              identity is None；fail-loud 直接上抛）
version != 2  →  fallback → 继续运行  禁止 ✓  （mismatches 含边界码；下游零调用）
missing version → 默认 2             禁止 ✓  （code=MISSING_IDENTITY_VERSION）
拒绝时改写 Producer 声明值            禁止 ✓  （declared_identity_version 原样保留 = 1）
```

**形状说明（如实登记）**：`interface_scope` 键在 M1 成功读取 manifest 后恒存在；M1/M2 早期返回（`manifest_read_error` / `source_bytes_error`）仅含原有五键且已 `gate=BLOCK`——失败同样发生在边界，下游不执行。该表述已写入 `_verify_identity_boundary` docstring。

**已知非阻塞语义细节（如实登记，未越权修改）**：既有权威 `_INTERFACE_IDENTITY_VERSIONS = {2, "2"}` 用集合成员判定，Python 中 `2.0 == 2` 为真，故数值 `2.0` 会被接受。JSON 中 Producer 声明为整数 `2`，此形态不构成实际输入；且收紧该判定属修改既有冻结权威的行为，超出「最小范围工程修正」，如需处置应单独授权。

## 附录 A：任务书 §4 技术问题（Q1–Q5）实证回答

### Q1 — 当前真正的 runtime entry point 是什么？

```text
1) scripts/preprocessing_consumer/runner_b2.py :: run_corpus     ← 主入口
   `python -m scripts.preprocessing_consumer.runner_b2`
   走完 preprocessing → V3 完整准入链（ResolvedRun → IR → Compiler → Gate → Candidate）

2) scripts/preprocessing_consumer/runner.py :: run_corpus        ← 次入口
   `python -m scripts.preprocessing_consumer.runner`
   Track A 直入生产 `GateService.run`；Track B 产 V3 ResolvedSpan

3) scripts/preprocessing_consumer/runner_b3.py :: run_experiment  ← 非 V3 入口
   仅读 manifest + source 行做 option label 检测实验，不进 IR/Compiler/Gate/Admission
```

### Q2 — 当前 identity validation 的完整路径？

```text
输入 manifest_path + source_path (+ resolver_ir_path)
  → _verify_identity_boundary                          runner_b2.py
  → M1 read_manifest_identity(manifest_path)           app/core/manifest_identity.py
  → M2 load_raw_bytes_identity(source_path)            app/core/raw_bytes_identity.py
  → M3 read_ir_identity(ir_path, source_file, source_sha)   app/core/ir_identity.py  （可选）
  → M4 verify_identity(computed, manifest, ir)         app/core/identity_verifier.py
  → M5 evaluate_identity_gate(verification)            app/core/identity_gate.py
  ★ → _declared_identity_version(manifest_path)        runner_b2.py
  ★ → enforce_interface_scope(sha, version)            boundary.py
  ★ →   normalize_interface_identity(sha, version)     boundary.py
  → 最终接受/拒绝点：_verify_identity_boundary 的返回值（gate=PASS|BLOCK）
       → run_corpus 据此决定是否调用 _run_full_chain（V3 semantic consumption）
```

### Q3 — `identity_version` 当前从哪里读取？真实数据流

```text
Producer manifest JSON 顶层键 "identity_version"      （int 2 | str "2" | null | 缺失）
   │  [verbatim，不解释]
   ▼
manifest_reader.load_manifest → Manifest.identity_version: int | str | None
   │                            （纯读取层，零转换）
   ├──► runner.run_corpus          → enforce_interface_scope(…, manifest.identity_version)
   │
   └──► runner_b2._verify_identity_boundary
            └─ _declared_identity_version(manifest_path)   ← 窄读同一声明字段
                 （M1 read_manifest_identity 按冻结设计**只**返回 source_content_sha256，
                   不读取 identity_version，故此处窄读补齐；本函数不判定、不默认）
                 └─► enforce_interface_scope(manifest_sha, declared_version)
                        └─► normalize_interface_identity(...)   ← 唯一判定权威
                               → NormalizedIdentity.identity_version = "2"（仅接受路径）
```

**不读取 `identity_version` 的组件（实证）**：`app/core/manifest_identity.py`（M1）· `raw_bytes_identity.py`（M2）· `ir_identity.py`（M3）· `identity_verifier.py`（M4）· `identity_gate.py`（M5）· `annotation_adapter.py` · `resolved_span_adapter.py`。这正是 F-INT-08 的成因。

### Q4 — 在哪里加入 `identity_version == 2` 最符合当前架构？

```text
集成边界（Integration Boundary）——具体为 _verify_identity_boundary 内、
M1–M5 之后、任何 semantic consumption 之前；判定委托 boundary.normalize_interface_identity。
```

**理由**：
1. `_verify_identity_boundary` 是所有 semantic consumption 的**既有单一闸点**（`_run_full_chain` 对 `gate==BLOCK` 短路），接在此处不新增并行控制流；
2. 与任务书 §2 的 runtime invariant 顺序一致：先证 identity 有效，再确认 Interface Scope 成员资格；
3. **优先复用**既有 `normalize_interface_identity`，不建第二套校验体系；
4. 不在 `IRBuilder` / `Compiler` / `Gate` 内重新判断——那是 V3 内部补救，且会触碰已 CLOSED 的 F-M3-04 / M.3。

### Q5 — 是否存在其他 runtime entry point 可绕过该检查？

**存在 1 个，已关闭**：`runner.py`（Track A 直入生产 `GateService.run`，此前零 interface identity 检查）。现已接入同一权威。

**存在 1 个，不构成绕过且未改**：`runner_b3.py`（不进入 V3 pipeline，见 §15.6.1 代码证据；受任务 §7.5 禁止扩大修改约束）。

**不存在**：alternate runner / fallback / catch-rewrite 绕过路径（见 §15.6.2–15.6.4 逐类证据）。
