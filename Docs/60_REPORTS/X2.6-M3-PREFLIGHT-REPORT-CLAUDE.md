## D. F-05-A Implementation Design（Preliminary）

### D.1 Authority Data Model

```text
Proposed (subject to Owner Decision on GAP-01/02/03):

@dataclass(frozen=True)
class MappingAuthorization:
    """A single Owner-authorized mapping with full semantic binding."""
    event_id: str              # e.g. "X2.6-OD-2-MAP-STANDALONE-01"
    source_value: str          # e.g. "standalone_question"
    canonical_target: str      # e.g. "standalone_unit"
    direction: str             # e.g. "legacy_to_canonical"
    decision_doc: str          # e.g. "X2.6-OD-2-MAPPING-AUTHORIZATION"
    status: str                # "authorized" / "prohibited" / "pending"
    condition: str             # additional evidence condition

Key difference from current MappingEntry:
  Current: mapping_basis is a string field on MappingEntry
  Proposed: event_id is bound to (source, target, direction) triple
  This enables semantic binding validation.
```

### D.2 Event → Mapping Binding

```text
Proposed binding structure:

AUTHORIZATION_REGISTRY: dict[str, MappingAuthorization] = {
    "X2.6-OD-2-MAP-STANDALONE-01": MappingAuthorization(
        event_id="X2.6-OD-2-MAP-STANDALONE-01",
        source_value="standalone_question",
        canonical_target="standalone_unit",
        direction="legacy_to_canonical",
        decision_doc="X2.6-OD-2-MAPPING-AUTHORIZATION",
        status="authorized",
        condition="...",
    ),
    ...
}

Binding validation:
  event_id → MappingAuthorization → (source_value, canonical_target, direction)
  The event_id MAPS TO a specific triple. Using the event_id for a different
  triple is detectable and rejectable.
```

### D.3 Validation Point

```text
Proposed validation point: gate/service.py, replacing _IR_TO_CANDIDATE_UNIT_TYPE

Current flow:
  root.unit_type → _candidate_unit_type() → hardcoded dict → candidate.unit_type

Proposed flow:
  root.unit_type → resolve_authorized_mapping() → validate_authorization() → candidate.unit_type

Validation function signature (preliminary):
  def resolve_authorized_mapping(
      source_value: str,
      claimed_event_id: str | None = None,
  ) -> tuple[str | None, str]:
      """Resolve source_value to canonical target with authorization validation.

      Returns:
          (canonical_target, provenance) if authorized
          (None, reason) if not authorized

      Fail-closed: any validation failure → (None, reason)
      """
```

### D.4 Fail-Closed Behavior

```text
Fail-closed rules:
  1. source_value not in registry → (None, "unmapped: no authorization record")
  2. event_id is fake (not in registry) → (None, "unauthorized: fake event")
  3. event_id exists but wrong source → (None, "mismatch: event does not authorize this source")
  4. event_id exists but wrong target → (None, "mismatch: event does not authorize this target")
  5. event_id exists but wrong direction → (None, "mismatch: event does not authorize this direction")
  6. event_id reused for different mapping → (None, "reuse: event already bound to different mapping")
  7. registry/governance mismatch → (None, "governance_mismatch: registry inconsistency detected")

  In all failure cases:
    - canonical_target = None
    - provenance = failure reason
    - Caller MUST NOT default to any canonical value
    - Caller MUST NOT silently skip
    - Production path: this unit should fail gate/admission
```

### D.5 Production Call Path (Proposed)

```text
gate/service.py run() method:
  For each IR unit:
    1. source_value = root.unit_type  (from IR)
    2. (canonical, provenance) = resolve_authorized_mapping(source_value)
    3. if canonical is None:
         → unit fails authorization check
         → record failure with provenance
         → do NOT create candidate (or create with rejection)
    4. if canonical is not None:
         → candidate.unit_type = canonical
         → record provenance in candidate payload
         → proceed with normal gate evaluation
```
