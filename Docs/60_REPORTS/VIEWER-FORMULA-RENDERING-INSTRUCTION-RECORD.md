# Owner 指令记录：公式渲染 + 数据真实性（双约束）

> 记录 Owner 关于 **E2E Acceptance Viewer 公式渲染**的指令，并附 DSH **只读**可行性核对结果。
> **本轮不动手**（未改任何文件）。
> 指令核心：**改善公式显示方式，不得改变被验收的数据。**

---

## 1. 指令内容（原样记录）

### 1.1 公式显示要求

| 数据类型 | 要求 |
|----------|------|
| 行内公式 | 印刷体显示（如 $x^2+y^2=r^2$） |
| 独立公式 | 居中排版，分数/上下标/根号正确 |
| 化学方程式 | 化学式、电荷、反应箭头正确 |
| 矩阵、分段函数 | 保留结构、对齐与分行 |
| **公式渲染失败** | **显示原始 LaTeX + 明确标记失败，不得隐藏内容** |
| 图片公式 | 保留原始图片，**不得用文本公式替换** |

### 1.2 实现原则（六条）

1. 原始数据不可变——渲染器只展示，不重写 `viewer_data.json` / `data.js` / V3 输出
2. 公式渲染与语义解析分离——不得借渲染之名改题干/选项/答案/公式内容
3. 渲染失败必须可见——保留原始公式并标注
4. 不把"渲染成功"等同于"公式正确"
5. Gate 1 与 Gate 2 都支持公式排版（便于前后比较）
6. 不触碰生产管线（Producer / Resolver / Gate / Schema / P1.4-B）

### 1.3 实施顺序（不得颠倒）

```text
① 恢复验收数据真实性：从原始 V3 输出重新导出，禁止任何自动补齐/切分，原值必须保留
② 增加只读公式渲染层（如 KaTeX；先查现有依赖与本地部署方式，避免引入不必要的外部运行时依赖）
③ 验证渲染正确性（分数/上下标/根号/矩阵/分段函数/化学方程式/非法 LaTeX）
④ 验证数据不变性（渲染前后原始数据 SHA256 不变；选项数量/文本/答案不变）
```

**最终验收标准**：你看到的是印刷体公式，同时仍然能看到真实管线生成的题目。
**如果题目本身有缺陷，渲染器必须如实呈现，不能替 V3 修好它。**

## 2. DSH 只读核对 A：渲染器必须覆盖的真实形态（已量化）

对 9 科 284 题的导出数据实测（`_survey_latex_shapes.py`，1,310 个文本字段 / 80,745 字符）：

```text
行内 $...$        704 处
独立 $$...$$       17 处
\frac              84        \sqrt          35
上标 ^             73        下标 _        127
\mathrm（化学）     16        \overset/\underset  23
\uparrow/\downarrow  3        \cdot/\times   46
\left/\right       11        \text{          3
\begin{...}         1        cases/displaystyle/arrow  0（本语料不存在）
```

**结论**：KaTeX 的常规子集足够；**不需要 mhchem**（化学用 `\mathrm` + 上下标表示）；
`cases` / `\to` 在本语料未出现，但建议仍保留负例测试。

### 2.1 ⚠️ 两个被指令遗漏、但会让渲染"看起来坏掉"的真实风险

**(a) 题干/选项文本里混着 HTML，公式渲染只是其中一半**

```text
<div 79    <img 58    <table 22    <tr/<td 160
```

即：渲染层必须同时处理 **LaTeX + HTML 片段**。若只接 KaTeX，`<div style=...><img .../>`
会以源码形式显示；若只接 HTML，数学公式会以 `$...$` 源码显示。
**建议**：渲染管线明确两段式——先 HTML 片段处理，再对文本节点做 $..$ 数学渲染；
图片（`<img>`）**原样保留**，符合指令 §1.1「图片公式不得用文本替换」。

**(b) 当前导出里存在"未闭合 `$`"的字段（渲染静默失败的真实来源）**

```text
字段中 $ 个数为奇数（无法配对 → 静默渲染失败）：8 处
   例：[answer/数学] '26.\n\n【考点】三角函数的化简求值… $ \\cos\\theta $ 的值，可得  $ \\tan\\theta $ 的值'
```

注意：这 8 处**全部出现在 `answer_text`**，而不是 `stem`/`options`。
原因是导出时对 `answer_text` 做了 `[:300]` 截断，**把公式从中间切断**。

⇒ 这正是指令 §1.2 第 3 条要防的失败模式，而且**根因是显示层的截断，不是数据**。
**必须在渲染层实现"未闭合 `$` → 原样显示 + 标注 RENDER_FAILED"**，否则公式会静默消失。

## 3. DSH 只读核对 B：**Gate 1 目前实际上跑不动**（比公式渲染更优先）

这一项与公式无关，但会决定 Gate 1 能不能用：

```text
app.js:50  document.getElementById('pdf-text').textContent = pdfPrev + …
app.js:53  const d = simpleDiff(pdfPrev, mdPrev);     ← diff 跑在 3000 字截断预览上
app.js:49  const mdPrev = s.md_text_preview || '';
```

实测长度（数学）：

```text
pdf_text_len = 10,231   但 preview 仅 3,000 → 只用了 29%
md_text_len  = 19,228   但 preview 仅 3,000 → 只用了 16%
```

**两个后果**：

1. **差异摘要只覆盖了 16–29% 的文本**——你按 Gate 1 扫差异时，**71–84% 的内容根本没被比较**。
2. 截断把公式**从中间切断**（§2.1b），制造出 8 处假的"未闭合 `$`"。

**好消息**：完整文本文件是存在的，导出里已有路径字段：

```text
pdf_text_path = 05_V3_OUTPUT/数学.pdf.txt      (9 份齐全)
md_text_path  = 02_PREPROCESSING_OUTPUT/….md   (9 份齐全)
```

**⇒ 修法很小**：Gate 1 改为读取 `*_text_path` 指向的完整文件（或页面直接 `fetch` 它们的副本），
而不是渲染 `*_text_preview`。

## 4. DSH 只读核对 C：Gate 1 的 diff 方法本身需要重新设计

我此前已实测（`_gate1_diff_prototype.py` / `_gate1_marker_diff.py`，只读）：

| 方法 | 实测结果 | 判定 |
|------|---------|------|
| 行级全文 diff（PDF vs MD） | 数学 **749 行中 153 行**被判"不同"，**0 个真实缺陷被命中** | ❌ 噪声压倒信号 |
| **按题号锚定的标记 diff**（比较选项标签集合/位置） | 化学 `D: PDF=23 MD=22`（**-1，正好命中 Q23 丢 D**） | ✅ 可行 |

页面当前用的是**行级全文 diff**，并且它自己也在输出里承认：

```text
"预览范围内未发现明显行级差异（仍需人工扫一眼全文）"
```

⇒ 这与 Owner §1.3 的"验收可用性"要求不一致：**一个噪声高、覆盖 16–29%、且对已知缺陷 0 命中的 diff，会把人工验收变成翻页劳动。**

**建议**（与公式渲染同为 Viewer 修复项，但独立）：
Gate 1 的差异区改为**两段式**：
- **A. 标记差异**（主）：按题号对齐，比较**选项标签集合 + 标签出现位置 + 题号序列**，只报差异。噪音有界。
- **B. 行级差异**（辅）：保留全文 diff，但**必须跑在完整文本上**，并作为次要参考。

## 5. 对实施顺序的建议修正（不改变 Owner 的优先级，只补两处前置）

Owner 的顺序是：① 恢复数据真实性 → ② 公式渲染 → ③ 验证渲染 → ④ 验证数据不变性。

**建议在 ① 与 ② 之间补两项**（否则 ② 做完 Gate 1 仍然不可用）：

```text
① 恢复数据真实性（重新导出，禁止补齐/切分，保留 raw）
①b Gate 1 改用完整文本（pdf_text_path / md_text_path），不用被截断的 preview
①c Gate 1 差异区增加「按题号锚定的标记 diff」作为主视图
② 公式渲染层（只读，作用于显示）
③ 渲染正确性验证
④ 数据不变性验证
```

**理由**：公式渲染解决"看不清"，而 ①b/①c 解决"看不全、看不对"。两者都是"验收可用性"。

## 6. 建议追加的验收判据（把指令 §1.3④ 变成可执行）

指令要求"渲染前后原始数据 SHA256 不变"。建议具体化为**三条 fail-closed 判据**：

| # | 判据 | 检查方式 |
|---|------|---------|
| S1 | `viewer_data.json` / `data.js` 在**渲染前后 SHA256 不变** | 渲染前后各取一次 sha 比对 |
| S2 | **除 `export_viewer_data.py` 外，验收目录内无脚本写入这两个文件** | 目录内脚本审查 + 文件 mtime 监控 |
| S3 | **哨兵记录**：`化学 Q20` 必须导出 **5 个选项**（含 `E='还原反应'`）、`数学 Q4` 的 option D 文本必须为 `'D'` | 在导出后自动断言；**不符即报警，禁止修复** |

**S3 是关键**：它是"渲染器没有替 V3 修好缺陷"的唯一可自动验证的证据。
当前这两条哨兵值**已被 `_improve_options.py` / `_fix_q4_opts.py` 改掉**
（Q4 的 D 变成 `关于直线 y= -x 对称`，label-only 选项数从 2 变成 0），
所以重新导出后 S3 应恢复为上述期望值。

## 8. 本轮结论

- 指令本身**正确且必要**：公式可读性确实影响验收效率，且"只改显示、不改数据"的边界划得对。
- 但只做公式渲染**不足以**让 Gate 1 可用——**截断（只比 16–29%）与 diff 方法（0 命中）是更前置的阻塞**。
- **建议把本任务范围定为**：`恢复数据真实性 + Gate 1 完整文本与标记 diff + 公式渲染 + 三项 fail-closed 判据`，
  作为**同一轮 Viewer 修复**，仍然**不碰任何生产逻辑**。
