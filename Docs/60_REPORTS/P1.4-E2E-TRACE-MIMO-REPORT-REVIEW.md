## 1. C1 核实：E 确实是 P1.4-B 新造（独立取证）

`.p14b.bak` vs 当前 manifest（`_review_mimo_trace.py`）：

```text
化学/Q20   BEFORE (bak): ['A','B','C','D']
           AFTER  (cur): ['A','B','C','D','E']   <<< CHANGED
化学/Q22   BEFORE: ['A','B','C','D']   AFTER: 同        （golden，未变）
化学/Q23   BEFORE: ['A','B','C']       AFTER: +D
历史/Q29   BEFORE: ['A','B','C']       AFTER: +D
数学/Q4    BEFORE: ['A','B','C']       AFTER: +D
```

**独立推理链**（不依赖 bak 的写法）：

1. `reference.py` 由 **manifest 的 `options[]`** 构造 `option_label` targets；
2. `resolver.py` 只遍历 `labels`（= manifest 声明），**不为未声明标签创建 option**；
3. bak 中 Q20 **未声明 E** ⇒ P1.4-B 之前不可能产出 E option；

⇒ **E 是 P1.4-B 引入的新结构。** MIMO 的自我纠错**成立**。

E 的实际内容（当前解析结果）：`E: len=4  '还原反应'`，
来源为源文 L159，即 D（L157 `D. 硫在自然界的循环过程中，涉及了氧`）的换行续文。
**D 因此被截断，E 是残片**——这不是「多一个选项」，而是**把一个选项劈成两个**。

## 2. C2 不成立：Q4 的 option 侧**确实**有缺陷（报告漏报）

报告的 §3 责任矩阵把 Q4 写成：

```text
Q4 | 2D. 在文中 | 相同 | annotation 漏 D / p14b 补 | labels 全，answer 仍 None | 选项无缺陷；answer-side
```

**实测当前 Q4 的解析 option spans：**

```text
数学/Q4  gate=pending_review
   A: len=23  'A. 关于 x 轴对称 B. 关于 y 轴对称'
   B: len=1   'B'                                    <<< LABEL-ONLY（空壳）
   C: len=32  'C. 关于直线 y=x 对称 2D. 关于直线 y= -x 对称'   <<< 吞掉了 D 的正文
   D: len=1   'D'                                    <<< LABEL-ONLY（空壳）
   degenerate options: ['B', 'D']
   !! option C text carries stray label token
```

`option D` 的解析文本是字面量 `'D'`（`granularity=line_character`，起点 = D 的字符 offset），
真正的内容 `关于直线 y= -x 对称` **仍在 option C 的 span 内**。

⇒ 两点与「选项无缺陷」矛盾：

1. **D 是空壳**：P1.4-B 并未让 Q4 获得 D 的内容，只是造了一个 label-only span；
2. **C 被污染**：C 的文本里带着 `2D. 关于直线 y= -x 对称`。

对照标准：MIMO 在 C1 用「**manifest label 变化**」证明 Q20 造假；
而 Q4 的缺陷恰好**不在 manifest label 上**（`['A','B','C']→['A','B','C','D']` 看起来是正确的），
而在**解析出的 span content** 上。**只查 manifest 层会漏掉 Q4。**

→ 这正是我上一轮报告中「断言层次只到 label、未到 content」的同类问题，
在 MIMO 报告里以另一种形式重现。

## 3. C6/C7：接口模型不完整——**正式链根本不消费外部 manifest**

报告 §1 给出三层：

```text
L0 Preprocessing（正式） Papers/Ocr-markdown/...      OCR→Markdown
L1 Annotation/manifest   *.manifest.json (reslice+LLM) 题号/选项标签/答案行号
L2 V3 consumer           preprocessing_consumer        manifest+md → Resolver → IR → Gate
```

**这对 Phase 1 实验链是准确的。但对正式产品链不准确。** 取证：

### 3.1 `preprocessing_consumer` 只存在于 `scripts/`，`app/` 完全没有引用

```text
glob  app/ 下 preprocessing_consumer  →  0 个文件
grep  app/  对 preprocessing_consumer / manifest 的引用 → 仅 identity_verifier.py /
      manifest_identity.py（只读 source_content_sha256 做身份校验，与选项结构无关）
```

### 3.2 正式链 V3 **自己**做标注

`app/domains/task/executor.py`：

```text
TaskExecutor（H Phase 8）：Worker 循环编排
编排 document_ingest 三 stage：Seal → Annotation → Compile
（Resolve + Compile + Gate + Admission 由 GateService.run 收口）

I-0-1 Prompt Contract Alignment：把 Frozen Annotation Payload Contract（20 §4.1–4.5）
真实写入模型输入。... LLM 只输出三字段（document_metadata_claims / sections /
semantic_units）... answer 只声明位置、不转录正文（20 §4.3）。
```

而实验 runner 的 task_type 是：

```text
task_type="preprocessing_consumer_phase0"   （runner.py / runner_b2.py）
```

⇒ **两条链并行且不同**：

| | 正式产品链 | Phase 1 实验链 |
|--|-----------|---------------|
| 入口 | `TaskExecutor`（`document_ingest`） | `scripts/preprocessing_consumer/runner*` |
| task_type | `document_ingest` | `preprocessing_consumer_phase0` |
| 题号/选项结构来源 | **V3 自己的 Annotation LLM** | **外部 manifest**（`reslice_pipeline` + LLM） |
| 是否消费 `Papers` manifest | **否** | 是 |

**因此报告那句「更接近架构 B / 结构在 manifest」需要限定**：
那只描述 Phase 1 实验链。在正式链中，**选项结构由 V3 自己的标注阶段产生**，
`Papers/Ocr-markdown` 的 manifest 根本不参与。

这使报告的结论**比它自己说的更强**：
Phase 1 不只是「实验变体、非正式生产链」，
而是**跑在一条正式链不使用的输入通路上**——
**Phase 1 的结论无法用来判定正式链的选项结构行为。**

⇒ 下一轮追踪必须走 **`TaskExecutor` / `document_ingest`**，
而不是继续在 `preprocessing_consumer` 上加深。报告 §5.3 的建议方向是对的，
但需要补上「换入口」这一关键点。

## 4. C3：Q22 是有效 golden，但选样偏窄

核实：Q22 `BEFORE == AFTER == ['A','B','C','D']`，解析后四个 option 均为正常正文
（len 47/68/62/36），无退化。**作为 golden 有效。**

但需注意选样局限：**Q22 与 Q20 同属化学卷同一 section**，
Q22 是单行选项、Q20 是换行选项。

- ✅ 好处：同卷同节，说明**不是整卷性缺陷**，是**逐题格式差异**；
- ⚠️ 局限：**只覆盖「本身无格式损伤」的题**。
  真正的 golden 还应包含**已知有格式损伤但结构仍正确**的题（例如 Q29 这一类），
  以证明「损伤 ≠ 结构错误」。

建议下一轮 golden 至少两例：**无损伤题 + 有损伤但正确题**。

## 5. 其他核实与补充

### 5.1 C9：Q20 确实未回滚

当前 manifest 仍为 `['A','B','C','D','E']`。报告「我未动」属实。

**回滚的注意点**：E 由**两处**产生，只删一处无效：
1. `化学 manifest` 的 `options[]` 中手工回填的 `E`；
2. `Papers/scripts/reslice_pipeline.py` 的 Rule A（会**再次**生成 E）。

⇒ 若决定回滚，必须**同时**处理 manifest 与 Rule A，否则重新生成即复现。

### 5.2 报告 §3 的「首次变化层」用词建议修正

报告把 Q4/Q23/Q29 的「首次变化层」都写成 `annotation 漏 D / p14b 补`。
更准确的分工是：

```text
Q4/Q23/Q29 的 label 缺失：首次变化 = annotation（外部 manifest 未声明 D）
                            —— Phase 1 实验链的 Producer 层
P1.4-B 的补 D：变更点 = manifest 回填（数据侧）+ Rule A/B/C（Papers 代码侧）
```

而**Q4 的 span 退化**：首次变化 = **P1.4-B 的 Rule B**（此前 D 无 span，不存在退化）。

### 5.3 Q20 还有一层报告未提：gate 仍然 auto

```text
化学/Q20  gate=auto_approve   （answer=B ∈ labels，校验不查选项内容）
```

即：**被改坏的 Q20 依然是 auto_approve**。
这印证了「Gate 数字不能作为数据正确性的证据」——
若只看 gate，Q20 的缺陷完全不可见。建议写入报告的「已证明」清单。
