## 1. 本轮只读核对已确立的事实

### 1.1 V3 的输入契约（已读到权威定义）

`AITutors-v3/backend/scripts/preprocessing_consumer/manifest_reader.py`：

```python
@dataclass(frozen=True)
class ManifestOption:
    """Producer 声明的单个选项 span（label + 行号区间）。"""
    label: str
    start_line: int
    end_line: int
```

模块 docstring：

```text
Preprocessing manifest reader — 只读，零 V3 依赖。
纯读取层：不做词表转换、不做校验、不改写 Producer 取值。
```

**结论（回答 Owner §八②）**：V3 消费的是

```text
① <paper>.manifest.json   —— Producer 声明：unit_type / stem_lines / options_lines /
                              options[label,start_line,end_line] / answer_lines / ...
② <paper>.md              —— 正文文本（resolver 用行号索引取文本切片）
```

`option_lines` 与 `options[].label` **都是 Producer 声明的**，
V3 不重算标签集合，只用它们去 source 行里**定位 span**。

→ 因此 V3 **不是**「重新拆原材料」的唯一责任方，但也**不是**纯消费者：
Resolver 仍在 source 行内做 label offset 定位（`_label_offsets`），
这属于 Owner 所说「架构 A 与 B 之间」的混合形态。**该边界尚未被任何冻结文档明确。**

### 1.2 结构化职责实际在 `reslice_pipeline.py`（+ LLM）

`Papers/scripts/reslice_pipeline.py` 头部 docstring（原文）：

```text
LLM 重切流水线（试点版）
流程：
  源 md（Ocr-markdown\{grade}\{subject}\，非 v6）
   → 行号化（[L0001] 前缀，供 LLM 受控引用，不转录正文）
   → LLM（正式 MIMO V2.6 PRO = mimo-v2.6-pro）按确认规则输出 semantic_units
     （仅行号引用+角色声明）
   → 确定性校验（行区间合法、题号覆盖、答案存在、composite 材料齐全）
   → 双格式产出：
      ① manifest JSON（V3 semantic_units 形态，无正文，供 Resolver/入库）
      ② 切片 md（题干区/答案区/详解区，展示形态）
规则：R1 完整题 … R2 共享前置材料 => 整合为一道综合题 R4 子题逐题齐全 … R9 卷面指令不入库
```

**结论（回答 Owner §八「谁负责 Question/Option/Answer 的结构化？」）**：
结构化职责在 **`reslice_pipeline`（LLM 注释）+ 确定性校验**，**不在 V3**。
`reslice_pipeline` 是 preprocessed markdown → V3 manifest 的**桥接/适配层**，
但也**同时是 `options[]` 的生产者**（P1.4-B 的 Rule A/B/C 正是加在这一层）。
