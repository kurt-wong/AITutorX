## 2. 独立发现的两个缺陷（报告未提及）

### 2.1 化学 Q20 — 换行续行被提升为**假 option E**（新引入）

源文：

```text
149: 20. 硫在自然界的循环过程如右图所示。下列说法中，不正确的是
151: A. 火山喷发、森林火灾会产生SO $ _{2} $
153: B. 氢、氧两种元素没有参与硫的
155: C. 工厂产生的烟气应经脱硫处理后再排放
157: D. 硫在自然界的循环过程中，涉及了氧      ← 印刷换行，句子未完
159: 还原反应                                ← 这是 D 的续行，不是第五个选项
161: 21. 下列行为不符合安全要求的是
```

L157 结尾「涉及了氧」+ L159「还原反应」= **「涉及了氧化还原反应」**，是一个被印刷换行的 D 选项。

`.p14b.bak` 对比证明 **E 是本次新增**：

```text
Q20 options  old: A(151) B(153) C(155) D(157)
             new: A(151) B(153) C(155) D(157) E(159)   ← 新增
```

**独立反证**：以**新 Producer 原始函数** `_detect_option_labels` 直接在 Q20 上运行
（`_p14b_producer_vs_manifest.py`），同样输出 `E`。
→ 该误报来自 **Papers 的 Rule A**，而非手工回填。

**replay 证据**：

```text
化学/Q20  gate=auto_approve  labels=['A','B','C','D','E']
   option D: granularity=line  lines=['P1L157']  compiled='D. 硫在自然界的循环过程中，涉及了氧'
   option E: granularity=line  lines=['P1L159']  compiled='还原反应'      ← 假 option
```

**影响**：Q20 现在会物化一个**内容为「还原反应」的第五选项**。
Q20 的 gate 仍 `auto_approve`（answer=B ∈ labels），**Gate 数字掩盖了这个数据缺陷**。
这正属于任务 §12 的告诫范畴：**不得把「Gate 未变」当作「数据正确」**。

### 2.2 数学 Q4 — 补出的 option D 是**空壳**（label-only）

```text
数学/Q4  gate=pending_review  labels=['A','B','C','D']
   option A: granularity=line            lines=['P1L021']  compiled='A. 关于 x 轴对称 B. 关于 y 轴对称'
   option B: granularity=line_character  lines=['P1L021']  compiled='B'                    ← label-only
   option C: granularity=line            lines=['P1L023']  compiled='C. … 2D. 关于直线 y= -x 对称'
   option D: granularity=line_character  lines=['P1L023']  compiled='D'                    ← label-only
```

**机制**：Rule B 在 `_label_offsets` 中把 offset 定位到数字之后的 `D`，
`_option_span` 随即构造 **`line_character` span，起点 = D 的 offset**，
于是 span 文本**恰好就是标签本身 `"D"`**，而真正的内容 `关于直线 y= -x 对称`
仍被**留在 option C 的 span 内**（C 的 compiled 文本里可以看到 `2D. 关于直线 y= -x 对称`）。

**两个后果**：

1. **内容丢失**：option D 的物化文本是 `"D"`，不是 `关于直线 y= -x 对称`
2. **内容污染**：C 的文本里带着 `2` 与 D 的正文

这与「不得修改 option content」的约束冲突——虽然 manifest 数据未被改坏，
但**解析产物**已经错位。（注：`option B` 的 label-only 是既有行为，非本次新增；
D 的 label-only 是 Rule B 引入的新路径。）

**注意**：MIMO 报告 Q4 为「Evidence repaired」。
严格说**不成立**：Q4 的 evidence 从「缺 D」变成了「有一个空的 D」，
**并未真正获得 D 的内容**。

## 3. 为什么 24 项测试没能拦住这两个缺陷

对 `test_p14b_option_label_compat.py` 做覆盖审计（`_p14b_test_coverage_audit.py`）：

| 覆盖维度 | 情况 |
|----------|------|
| 换行/续行内容被提升为新 option（Q20 缺陷形态） | **0 / 18 测试覆盖** |
| 断言修复后 option 的**解析文本非退化**（Q4 缺陷形态） | **0 / 18 测试覆盖** |
| 词法级（regex 命中/不命中） | 覆盖充分 |
| `_expand_option_spans` 合并逻辑 | 覆盖充分 |
| `_detect_option_labels` 产出 label 列表 | 覆盖充分 |

根因：测试全部断言在 **label 列表 / regex 命中**这一层，
**没有任何一项断言 option 的 content**，也没有任何一项构造**换行续行**语料。
→ 两个缺陷都发生在「label 正确但 span/content 错误」的层面，正好落在测试盲区。

**结论**：测试数量（24）与负面测试覆盖符合任务要求，
但**断言层次偏低**——只证了「字母对」，没证「内容对」。

## 4. 建议（按优先级）

### 必做（建议在 P1.4-B 内收口，均属同域小改）

1. **Rule A 增加续行排除**：末标签之后的候选行，若**紧邻的前一 option 行未以句末标点结束**，
   或该候选行**不构成新的、与 A/B/C 平行的选项起始形态**，则**不新建 label**，
   而应作为前一 option 的续行（或直接不处理）。
   最小判据可用：「前一 option 行末尾无 `。．！？；` 等终止符 → 视为续行」。
2. **Rule B 修正 span 构造**：digit-glue 命中时，option 的 span 应从**内容起点**开始，
   而不是从 label 字符 offset 开始；同时**不得**把 `2D.` 留在前一 option（C）的文本里。
3. **补 3 个测试**（断言层次升级）：
   - Q20：续行 `还原反应` → **不得**产生 option E（且 D 仍为 `P1L157`）
   - Q4：option D 的**解析文本必须等于** `关于直线 y= -x 对称`
   - Q4：option C 的解析文本**不得**包含 `2` 或 `D.` 之后的正文

### 必做（流程）

4. **`rejected = 5` 的作用域必须在报告里写全**。
   leaf 作用域 = 5；**root 作用域 = 62**（其中 57 个就是 IR incomplete 的 root）。
   本次未漂移，但若未来某次修复改变了 ready 集合，`rejected` 会跳到最多 62，
   单一数字会导致假警报。

5. **明确 manifest 的产出方式**。
   本次为**手工回填 + `.p14b.bak`**。DSH 已独立验证：以新 Producer 原始函数在
   **9 卷 176 个带 `options_lines` 的 unit** 上重放，产出与被回填的 manifest
   **完全一致（176/176，无 add 无 lose）**，故**回填是忠实的、非伪造**。
   但流程上应改为**重新生成 manifest**，而不是手工编辑语料数据
   （否则与「不得修改 Producer 数据」的原则冲突，且不可审计）。

6. **清理 4 个未跟踪的一次性 patch 脚本**，或归档到明确位置。
