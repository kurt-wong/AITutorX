## 2. 三个样本的 source 事实核对（已重新验证）

### 2.1 化学 Q23 — **label 完全缺失，不是「label 存在但受损」**

源文 L186–L194：

```text
186: 23. 下列反应的离子方程式书写不正确的是
188: A．金属钠与水： $ 2Na + 2H_{2}O = ... $
190: B．氯化钠溶液与硝酸银溶液：
192: C．稀盐酸与碳酸钙： $ CaCO_{3}+2H^{+}=... $
194:  $  \mathrm{H}^{+} + \mathrm{SO}_{4}^{2-} + \mathrm{Ba}^{2+} + \mathrm{OH}^{-} = \mathrm{H}_{2}\mathrm{O} + \mathrm{BaSO}_{4} \downarrow  $
```

manifest：`options_lines=[188,194]`，`options=[A(188), B(190), C(192)]`。

**关键事实**：L194 **没有任何 label token**，也没有 `D．`。它是**裸内容行**。

→ ⚠️ 授权书 §2 表格把 Q23 描述为「`D．` label 与 trailing option content 的形态」；
授权书 §5 **Rule A** 描述为「识别 `D．<option content>`，其中 **label token 本身存在**」。
**这两处描述与 source 事实不符。** Q23 实际属于 **B1 = label 完全丢失 → 只能由 trailing content 识别**，
不存在可匹配的 label token。

这直接影响 Rule A 的定义：若实现按「匹配 `D．` token」来写，**Q23 不会被修复**。

### 2.2 数学 Q4 — `2` 不属于 C 内容

```text
21: A. 关于 x 轴对称 B. 关于 y 轴对称
23: C. 关于直线 y=x 对称 2D. 关于直线 y= -x 对称
```

owner `options_lines=[21,23]`，`options=[A,B,C]`。

⚠️ 授权书 §5 **Rule B** 写到：「`2` **属于前一 option content 的尾部**」。
这与已确证结论不一致：`2` 是**标签边界粘连/污染**，**既不是 C 内容、也不是 D 内容**
（已由三语料变体 + 平行结构 + 无干净 `D.` 形态共同证明，见阶段 1 报告）。

**实现影响**：若按 Rule B 字面实现（把 `2` 归给 C 的尾部），会**污染 C 的 option content**
（`关于直线 y=x 对称 2`），属于修改 option content — 授权书 §3/§5 均不允许。
正确做法：`2` 应被**丢弃**（label-boundary contamination），D 的 content = `关于直线 y= -x 对称`。

### 2.3 历史 Q29 — 与授权书描述一致

```text
301: A. 迪亚士      303: B. 达，伽马      305: C. 哥伦布      307: D 麦哲伦
```

label token `D` 存在，仅缺 `.` 分隔符。Rule C 描述准确。
但须注意：**Q29 现在已经是 auto_approve**（`answer=C ∈ [A,B,C]`），
本修复对它**只改善 Option Evidence completeness，Gate 无收益**。

## 3. 实施前风险登记（R1–R6）

### R1 — Q23 的 label 字母只能由「位置枚举」确定，且会与 Q29 的形态重叠

Q23 完全没有 label。可用的 Source-local 确定性证据只有：

1. 内容行位于 `options_lines=[188,194]` 内（**满足**授权书 §4 的边界前置条件）；
2. 位于最后一个已识别 label（C @192）之后；
3. 与 A/B/C 同为「反应式/离子方程式」形态。

由此只能推出「**这是第 4 个 option**」，**推不出字母 `D`**——
字母来自「A,B,C 之后的第 4 个字母」这一**位置枚举约定**，而非 source 中的 token。

**建议（待 Owner 确认）**：把 Q23 的规则独立表述为
「**unlabeled trailing option within options_lines → 按 label 序列位置赋下一个字母**」，
而不是并入 Rule A「`D．` token 识别」。两者证据结构不同，不应合并为同一条规则。

### R2 — Rule C 需要「排除解析正文」但授权书禁止扩大边界

`SPACE_SEP` 在 `options_lines` 内命中 1 次（真阳 Q29）；
但在 `options_lines` **外**有 8 次假阳，例如历史 L749：

```text
B 是 1945 年，C 欧盟建立是 1993 年，D 美国 9.11 事件是 2001 年，均与冷战时间不符，排除 BCD。
```

该行位于**解析区**。授权书 §4 规定「必须先满足 `candidate evidence ∈ options_lines`」——
则 L749 天然被排除，**无需额外规则**。但必须有**显式 negative test** 锁定
「同形文本位于 options_lines 之外 → 不得成为 option」，否则后续重构容易把边界条件丢掉。

### R3 — 不变量表混用了 root 作用域与 leaf 作用域（会导致假警报）

授权书 §12 要求同时保持：

```text
root = 284 | incomplete = 57 | rejected = 5 | ready = 227
```

阶段 1 对账已证明（`_p14b_scope_reconciliation.json`）：

| 作用域 | auto | pending | rejected | 合计 |
|--------|------|---------|----------|------|
| **leaf** | **154** | **68** | **5** | 227 |
| root | 154 | 68 | **62** | 284 |

`rejected=5` 是**定义在 IR ready 的 227 个 leaf 上**；
root 作用域的 rejected = 62（其中 57 个就是 IR incomplete 的 root）。

**风险**：若本次修复使某个 root 变为 not-ready（或反之），
`rejected` 会从 5 跳到最多 62 —— 而这不必然是回归失败。
建议报告时**成对报告**：`ready=227 & incomplete=57 & rejected(leaf)=5 & rejected(root)=62`，
避免用单一数字判断回归。

### R4 — 本修复的收益不是「auto 变好」而是「Evidence 变全」

按授权书 §11 必须逐样本报告。预期（已双向独立确认）：

| Sample | old labels | new labels | old answer | new answer | old gate | new gate | Gate Δ | Evidence Δ |
|--------|-----------|-----------|-----------|-----------|----------|----------|-------:|-----------:|
| Chemistry Q23 | A,B,C | A,B,C,D | D | D | pending | **auto** | **+1** | repaired |
| Math Q4 | A,B,C | A,B,C,D | None | None | pending | pending | 0 | repaired |
| History Q29 | A,B,C | A,B,C,D | C | C | auto | auto | 0 | repaired |

`sum Gate Δ = +1`；`sum Evidence Δ = 3 repaired`。
**报告必须把这两个数分开写**，不得写「B 修复使 Gate +3」。

### R5 — Q29 是「已 auto」的样本，注意不要把它算进增益

Q29 的 `answer=C ∈ [A,B,C]` → `verify=True` → 已经 auto。
它的 B 分类来自**审计普查**（source 有 4 项但只声明 3 项），不是 Gate 缺陷。
→ 报告措辞必须是「Q29 = Option Evidence completeness improvement，**不是** Gate improvement」。

### R6 — D29 不得被本次修复重新计数

授权书 §12 明确：**D29 不得因本次 B 修复被重新解释或重新计数为 bug**。
实施后若 `option_blocks` 计数发生变化（例如 Q23/Q4/Q29 所在 unit 的 block 数变化），
必须确认 D29 的判据（`is_comp AND option_blocks>=2 AND n_leaves<len(sub_qns)`）
**不因此漂移**。三样本均为 `standalone_question`（非 composite），预期无影响，
但仍应在 replay 中显式核对 `D=29` 与 `C=1` 均不变。

### R7 — 验证范围的地域问题（流程风险，非技术风险）

阶段 1 的 read-only replay 用 `D:\Project\AITutors-v3\backend` 的模块 + 本仓 `e2e_run` 语料。
若实现改动落在 `AITutors-v3`，而语料/manifest 在本仓，
则「真实 replay」必须明确**使用修改后的 Producer 重新生成 manifest**，
否则 replay 读到的仍是**旧 manifest 的 `options[]`**（`options=[A,B,C]`），
会得出「修复无效」的错误结论。

→ 建议在阶段 4 交付中明确：manifest 是**重新生成**还是**手工修补**。
若为手工修补 manifest，则属于**修改 Producer 数据**（AGENTS.md 禁止），需 Owner 明确授权。

## 5. 结论：可以进入阶段 4，但先修正两处描述

授权本身清晰且边界足够。但**授权书 §2/§5 对 Q23 与 Rule B 的描述与 source 事实不符**，
若照字面实现会分别导致：

- **Q23 修复失败**（按「匹配 `D．` token」写 → 该 token 不存在）

→ 建议在实施前把这两处描述更正为：

```text
Rule A' (Q23) : unlabeled trailing option inside options_lines
                -> label letter by position in the A/B/C label sequence
Rule B  (Q4)  : DIGIT_GLUE `2D.` ; the leading digit is DISCARDED as
                label-boundary contamination (NOT appended to previous content)
Rule C  (Q29) : SPACE_SEP `D <content>` inside options_lines
```

其余授权内容（唯一目标、Authority 红线、options_lines 前置、negative tests、
boundary 禁改、Q4 answer-slice 禁改、Gate 禁改、逐样本报告、不变量、STOP 条件）
