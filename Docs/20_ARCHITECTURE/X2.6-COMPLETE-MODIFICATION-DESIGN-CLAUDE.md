# A. Executive Summary

X2.6 设计任务的交付物是一份**证据支持、可供实现引用、但不构成实现授权**的完整修改设计。

**核心事实（本轮直接验证）**:

1. Owner 目标 canonical Unit-Type = `{standalone, composite}`；Composite 是 **Unit-Type**，不是 Question-Type。历史词表 `{standalone_question, composite_question, andalone_question}` 与 V3 A-domain 词表 `{standalone_unit, composite_unit}` **三层并存**，尚未收敛。
2. Contract / DEC-028 **已经裁** Semantic Status 词表 = `{ready, incomplete, unknown}` 与路由 `unknown → reviewable record → pending_review`，并禁止 silent skip/convert/fallback。V3 实现侧 `SEMANTIC_STATUS` 仍冻结为 `{ready, incomplete}`（`compile/__init__.py:29`），**无 unknown**。
3. 仓库级穷尽检索确认 **UNKNOWN/legacy/missing → standalone 或 composite 的隐式路径确实存在**（P1–P13），且跨层方向不一致：同一非法值在 annotation adapter 被 wash 成 standalone，在 span/runner 路径被推成 composite。
4. Preprocessing **已经产出**大量 Composite 语义证据（unit_type / material_lines / question_numbers / prompt 规则），但历史操作化偏 material-centric，且 **producer write path 零闭集守卫**。证据 ≠ Admission Authority。
5. IR **结构上**能表达 Composite Unit + 多 Question + 各自 Question-Type + shared Material；**不能**表达 independent-answerability / UNKNOWN unit_type / grouping provenance。
6. Material impact 分析完成：当前代码形态 ≈ DB 层接近 Option B + compiler/gate 层接近 Option A。**Standalone Material 模型 = OWNER DECISION STILL REQUIRED**。
7. AITutor-X production = 空骨架（仅 .gitkeep）。全部可实施代码变更落在 V3 / Papers baseline，**均须 Owner 授权**。
8. 本轮 **零** production/test/preprocessing/V3/Papers/corpus/Contract 修改；**零** 关闭治理项；**未** push。

**设计结论（供 Owner 审阅，非代裁）**:

- 语义权威链应为：**Preprocessing 发现证据 → Manifest 保留证据 → Adapter 保真传输 → IR 规范化表示 → Compiler 确定性消费 → Gate 结构验证 + 闭集 enforcement → Admission 不重释义**。
- UNKNOWN 必须成为**显式可保留状态**，而非被 wash/binary/skip 消灭。
- 词表迁移必须**渐进、双读、可回滚**，禁止 find/replace 与一次性 rename。
- Composite Evidence 必须 **append-only + provenance**，语义结论可修订，历史证据不可抹除。

# F. UNKNOWN Model

## F.1 白话解释（任务书 §6 要求）

当系统遇到它**无法安全判断**的 Unit-Type 时——例如值是 `andalone_question` 这种拼写噪声，或 preprocessing 说 A 而结构证据说 B，或根本没有 unit_type——系统**现在**的做法是：有的地方把它当成 standalone，有的地方当成 composite，有的地方直接跳过。这些做法都让「不知道」这件事消失了，于是下游无法审计，也无法回头修。

**正确做法不是「假装知道」，也不是「扔掉」**，而是：

1. **承认不知道**（记为 UNKNOWN）；
2. **保留现场**（原始值、来源、冲突双方、行号都留着）；
3. **挡住生产**（UNKNOWN 不得变成正式题目入库）；
4. **留下可审查的记录**（reviewable record）；
5. **允许以后解决**（人工裁决 / 补充证据后重跑 / Owner disposition）；
6. **解决过程本身也要留痕**（谁、何时、依据什么、从 UNKNOWN 变成了什么）。

一句话：**UNKNOWN 可以存在，可以传递，可以被观察，可以被解决；但不可以被洗成 standalone，不可以静默消失，不可以直接进题库。**

## F.2 语义状态词表

Contract / DEC-028 **已经裁**（本轮亲读 Papers FC-3 + V3 contract DRAFT）：

```text
Semantic Status = {ready, incomplete, unknown}
Decision Status = {pending_review, approved, rejected}
禁止合并两套词表
unknown → reviewable record → pending_review
禁止 silent skip / silent conversion / silent fallback
```

V3 现状：`SEMANTIC_STATUS = {ready, incomplete}`（`compile/__init__.py:29`），**实现未跟上已裁词表**。

### ready / incomplete / unknown 的精确区分（本设计提议，供 Owner 确认操作化）

| Status | 含义 | 典型触发 | 可否进 Compiler/Gate/Admission 生产路径 |
|--------|------|----------|------------------------------------------|
| **ready** | Unit-Type 在**当前层允许的闭集内** + 结构完整 + 证据一致 + 引用可解析 | canonical standalone/composite 且 stem/answer/span 齐备 | YES → 正常编译与 Gate |
| **incomplete** | 已知语义方向，但**输入/结构不足**（缺 stem、span 未解析、缺 material、题型 unknown 等）；**补数据后可能变 ready** | missing span、unsupported role、composite 无 shared material | **NO 生产**；可 skip 并保留 reason；修复输入后可重试 |
| **unknown** | **无法安全判断语义身份**：Unit-Type 不在闭集 / legacy 无法安全映射 / 证据冲突 / 信息不足到无法定类 / 显式标 unknown | `andalone_question`、`composite_question` 在未授权映射前、manifest 与 annotation 冲突、缺 unit_type 且无结构证据 | **NO 生产**；必须保留 + reviewable record + pending_review 路由 |

**关键区分**:
```text
incomplete = 知道方向，材料不够（可修复输入）
unknown    = 不知道/不能信方向（须语义裁决或权威映射）
```

**冲突证据**: 可导致 `unknown`（若无法判定何方为准）或 `contested` 子状态；**不得**静默择一。

**缺失 Unit-Type**: → `unknown`（**不是** standalone）。

**非法/legacy 词汇**: 在 Owner 授权的显式映射表覆盖前 → `unknown`；映射后仍须保留 `source_vocabulary` provenance。

## J.3 四种职责分离（必须写进实现纪律）

| Kind | Meaning | Owner layer |
|------|---------|-------------|
| **semantic discovery** | LLM/规则发现证据与候选 | Preprocessing / semantic review |

## J.4 Authority Chain（证据权威）

```text
发现权威（meaning discovery）     = Preprocessing LLM / authorized semantic review
表示权威（canonical meaning）     = Canonical IR representation
映射权威（vocabulary mapping）    = Owner-authorized mapping table ONLY（CL-21 未裁前空缺）
验证权威（structure/safety）      = Gate policy + Compiler invariants
入库权威（production admission）  = Decision state machine + Admission
```

**现状与目标的差异（documented discrepancy）**:
```text
现状：normalization 行为散落在 adapter / IR / runner / Gate mapping / payload else
      —— 无单一 authority owner（CL-21 OPEN）
目标：normalization 只允许发生在 Owner 授权层；其余层 unknown/preserve
      —— 与 Owner「LLM 发现；IR 表示；Gate 验证；Admission 不重释义」一致
```

**禁止**: 第二个语义分类器（Gate 重猜、Admission 重猜、adapter 静默改写）。
