# 3. OD-MAP-01 — Legacy → Canonical Mapping

## Decision [PROPOSED — C]

Legacy 词汇进入 canonical semantic pipeline 时的处理规则如下：

### 3.1 `standalone_question`

**Chosen Rule**:
```text
preserve legacy value on the unit
+
record provenance (source_vocabulary, source_value)
+
interpret evidence (structural, material, semantic context)
+
resolve canonical Unit-Type through the authority chain (§10 OD-CL21-01)
```

**禁止**:
```text
standalone_question → standalone_unit  的无条件字符串映射
```

**理由**: Owner D1 裁定 `standalone_question` 不是 canonical Unit-Type；D7 裁定 legacy 是 evidence 不是 authority。即使语义方向接近，仍必须经过 evidence interpretation，而非词面自动映射。

**但方向性事实必须承认**:
```text
在当前 corpus 中，standalone_question 的原始定义（prd.md:85）
= 「无共享材料的独立题」
与 Owner D1 standalone_unit 的方向接近
但不等同：Owner 核心 = 可独立解答成立 + 不排除 Material（D6）
```

因此：**方向性接近 ≠ 无条件授权**。映射仍须 Owner OD-MAP 授权（见 §3.4 mapping table）。

### 3.2 `composite_question`

**Chosen Rule**:
```text
composite_question ≠ composite_unit（词面不自动等同）

何时 legacy composite_question 的证据足够支持 canonical composite_unit？
→ 当 evidence chain 完整且符合 D2 Condition A 或 B 时

Evidence 字段属于 evidence 的:
  - material_lines（shared material evidence）
  - question_numbers（explicit grouping evidence — 辅助）
  - prompt version + generation context（provenance）
  - questions_lines / stem_lines 结构形态

仅是 legacy label 的:
  - unit_type 字段本身的值 "composite_question"
  → 仅提供 vocabulary layer identity，不提供 semantic authority

进入 UNKNOWN 的情况:
  - Owner mapping table 未对该值授权
  - evidence 不足以确认 D2 Condition A 或 B
  - conflicting evidence（manifest 说 composite 但结构证据说 standalone）
  - missing critical evidence fields

需要 human review 的情况:
  - evidence 部分支持但不完整
  - cross-layer conflict（adapter vs span vs IR 对同一 unit 不同判定）
  - 单元既有 composite 特征又有 standalone 特征
```

### 3.3 Legacy → Canonical Authority Boundary

**Chosen Rule**:
```text
Legacy Producer
      ↓  provides: raw unit_type + evidence fields + provenance
Evidence (interpretation)
      ↓  produces: evidence items + candidate semantic classification
IR Semantic Resolution  ←── Owner-authorized mapping table (唯一映射权威)
      ↓  produces: canonical Unit-Type + semantic_status + provenance
Compiler
      ↓  consumes: ready + canonical only
Gate
      ↓  validates: closed-set + structural invariants + evidence consistency
Admission
      ↓  persists: verified canonical structure + evidence
```

**规则**:
```text
Producer 自己不是 canonical authority
Producer 提供 evidence 和 candidate interpretation
IR semantic resolution（配合 Owner-authorized mapping）形成 canonical interpretation
Compiler / Gate / Admission downstream 只消费，不重新解释
```

### 10.2 最终 Authority 声明

```text
Authority（semantic normalization）= IR Semantic Resolution + Owner-authorized mapping table

Producer role   = evidence producer + candidate interpretation
                  不是 canonical authority
                  提供 raw values + evidence + provenance

Transport role  = manifest + adapter + span adapters
                  保真传输
                  不 wash、不发明语义、不修改词面

Normalization role = IR Semantic Resolution
                     配合 Owner-authorized mapping table
                     把 evidence + candidate 转为 canonical representation
                     unmapped → semantic_status=unknown + reviewable record
                     NEVER default standalone

Validation role = Gate + Compiler invariants
                  structural validation + closed-set enforcement
                  不重新解释语义

Admission role  = Decision state machine + Admission persistence
                  拒绝 unresolved UNKNOWN
                  append-only admission event
                  不重新解释 Unit-Type
```

### 10.3 为什么是 IR Semantic Resolution

| Reason | Evidence |
|--------|----------|
| IR 是 canonical semantic representation 的定义层 | `compile/ir.py` docstring：IRBuilder 装配 + 校验不变量 |

| IR 已有校验机制 | `validate_ir` + `SEMANTIC_STATUS` 值域检查 + fail-loud |
| Producer 不应成为 authority | D4：Independent Answerability = LLM 语义 + evidence + human review，不是 producer 自说自话 |
| Gate/Admission 不应重新解释 | D9：Gate = Structural Validator；不重释义 |
| Adapter 应保真传输 | D7：legacy = evidence；adapter 不应 wash |

### 10.4 映射执行规则

```text
IR Semantic Resolution 执行规则:

1. 读取 unit_type raw value
2. 检查 Owner-authorized mapping table
   - hit + authorized → apply mapping + record provenance (mapping_basis = event id)
   - hit + pending_owner → semantic_status = unknown + reviewable record
   - miss → semantic_status = unknown + reviewable record
3. 检查 structural evidence
   - evidence 完整 + 与 mapping 一致 → semantic_status = ready
   - evidence 冲突 → semantic_status = unknown + reviewable record（不 silent resolution）
   - evidence 不足 → semantic_status = incomplete 或 unknown（取决于缺失类型）
4. NEVER: default standalone / binary composite / wash
5. mapping table 中的值必须由 Owner decision event id 授权
```
