## 1. Unit 与 Question 的边界（Owner Decision，逐字固化）

### 1.1 Unit

> **Unit 是组织和分组层级。**
> 它回答：
> 这一组 Question 在原始题目语义上是否属于一个共同的解答结构？

### 1.2 Question

> **Question 是最小的、可被独立识别和处理的题目粒度。**
> Question 有自己的 Question-Type。

### 1.3 Composite 的层归属

> **Composite 不是 Question-Type。**
> **Composite 是 Unit-Type。**

**Question-Type 示例（Owner 列举，非穷举）**:
```text
single_choice / multiple_choice / true_false / fill_blank /
calculation / proof / experiment / …
```

**标签**: `OWNER-INSTRUCTION`（本轮分析与实现的语义基准）。

## 3. Composite Unit 的正式定义（Owner Decision，语义基准）

> **若干 Question 共享材料、共享前提条件，或者题目/文档明确注明这些 Question 属于同一组；并且当组内任意 Question 脱离其所依赖的共享材料、共享前提条件或共享上下文后无法独立完成解答时，这些 Question 形成一个 Composite Unit。**

### 3.1 共享 Material

Question 依赖同一份文本 / 图表 / 图片 / 实验数据 / 装置 / 数据表 / 其他共享 Material，**可以**形成 Composite 语义依据。

> **「存在共享 Material」本身不能机械等价于 Composite。**
> 必须进一步判断 Question 与共享 Material 是否存在 **语义上的解答依赖**。

### 3.2 共享前提条件 / Context

Question 共享前提条件 / 背景设定 / 场景 / 上下文 / 公共变量 / 公共实验条件 / 公共假设，**可以**形成 Composite 语义依据。

> **单纯共享一个 context 字段，不应机械等价于 Composite。**
> 需要识别 Question 是否实际依赖该共享结构。

**标签**: `OWNER-INSTRUCTION`。

---

## 4. 独立可解答性依赖（Owner Decision — 本轮关键新增）

### 4.1 核心定义

> **如果一个 Question 脱离其所在组共享的 Material、共享前提条件或共享上下文后，无法独立完成解答，则该 Question 对该共享结构具有不可剥离的解答依赖。**

当拟归入同一 Unit 的 Question 集合中存在这种不可剥离的解答依赖，并且这些 Question 因此共享同一解答上下文时，该集合具有形成 Composite Unit 的语义依据。

### 4.2 禁止机械 `any()`

> **不得把上述定义粗暴实现成：**
> `if any(question_cannot_answer_alone): unit_type = "composite"`

本定义不是脱离语义上下文的纯布尔规则。需要分析：

1. Question 依赖什么？
2. 依赖的是哪一个 Material / prerequisite / context？
3. 该依赖是否是完成 Question 所必需的？
4. 脱离共享结构后是否真的无法完成解答？
5. 这些 Question 是否因此属于同一个语义解答结构？

### 4.3 必须区分的概念（不得混成一个字段）

```text
共享 (shared)
依赖 (depends on)
不可独立解答 (non-independent answerability)
显式分组 (explicit grouping)
```

**标签**: `OWNER-INSTRUCTION`。

## 5. 显式分组（Owner Decision）

> **如果题目或原始文档明确注明多个 Question 属于同一组，则这是 Composite Unit 的直接语义证据。**

**示例**:
- 「根据以下材料回答第 1～3 题」
- 「完成下列各题」
- 「根据图 X 回答 1～4 问」
- 「某实验包含以下三个问题」
- 文档显式 group metadata

### 5.1 不足以证明 Composite 的单列情形

> **连续编号本身不是 Composite 证据。**

以下情况 **单独都不足以** 证明 Composite：

```text
Question 连续编号
位于同一页
位于同一 section
OCR 中连续出现
版面相邻
使用同一题号前缀
```

**标签**: `OWNER-INSTRUCTION`。

## 6. Composite 的核心（Owner Decision）

> **Composite Unit 的本质是多个 Question 之间存在共享结构、显式分组或不可剥离的解答依赖，而不是它们在文档中连续出现。**

```text
Q1 Q2 Q3 连续出现 → 不能仅凭编号判断 Composite
Q1 Q2 Q3 共享材料 / 前提 / 显式分组 / 依赖不可剥离 → 应分析 Composite 语义
```

**标签**: `OWNER-INSTRUCTION`。

## 7. Standalone 定义边界（Owner Decision）

Standalone Unit 通常对应一个 Question。其核心 **不是**「这个 Question 没有 material 字段」，而是：

> **该 Question 在其自身必要信息范围内能够作为独立的解答单元成立，不存在必须依赖另一个 Question 所共享的 Material / prerequisite / context 才能完成解答的结构依赖。**

### 7.1 禁止的判定模式

```python
missing_material -> standalone
unknown_group -> standalone
unknown_unit_type -> standalone
invalid_unit_type -> standalone
```

**标签**: `OWNER-INSTRUCTION`。

## 8. UNKNOWN 原则（Owner Decision，逐字固化）

> **UNKNOWN ≠ standalone**

任何以下情况都 **不能** 静默归入 `standalone`：

```text
信息不足
Unit-Type 无法判断
preprocessing 与 IR 冲突
manifest 与 annotation 冲突
显式 grouping 与结构推断冲突
Material dependency 无法确认
Question independent answerability 无法确认
非 canonical Unit-Type
malformed / invalid metadata
legacy vocabulary 无法安全映射
结构信息丢失
```

### 8.1 禁止代码模式

```python
.get("unit_type", "standalone")

if unit_type == "composite":
    ...
else:
    standalone
```

**标签**: `OWNER-INSTRUCTION`。

## 9. Preprocessing → IR → Gate 职责（Owner Decision）

### 9.1 Preprocessing

Preprocessing **不是**「什么都不知道，只输出 Question」。其 LLM metadata 已包含大量结构证据。

Preprocessing **可以**:
- 发现结构
- 标记候选 Unit-Type
- 标记 Material dependency
- 标记 grouping
- 标记 Question relationship
- 提供 independent-answerability 所需语义证据

Preprocessing **输出的是**:
> **semantic evidence / candidate interpretation**
> **不是** 最终 Admission Authority。

### 9.2 IR

> **IR 的职责是将 preprocessing 产生的结构证据组织、规范化为 canonical semantic representation。**

IR 应能够表达至少:

```text
Unit / Unit-Type / Question / Question-Type
Material / Context / prerequisite / grouping
Question ↔ Material dependency
Question ↔ Context dependency
Question ↔ Unit relationship
semantic status / uncertainty
```

**必须区分**:
```text
Unit-Type = standalone / composite
vs
Question-Type = single_choice / calculation / proof / ...
```

**必须能够表达**:
```text
Composite Unit
    ├── Question A (own Question-Type)
    ├── Question B (own Question-Type)
    └── Question C (own Question-Type)
```

### 9.3 Gate

> **Gate 不是第二个 LLM semantic guessing engine。**
> Gate 的核心职责是：**验证已经形成的 semantic structure 是否满足 Admission 所需的结构约束。**

Gate 需要检查:
- canonical Unit-Type
- Unit ↔ Question relationship
- Composite 是否具有相应结构证据
- Material / context dependency 是否与 IR 一致
- Question-Type 是否独立于 Unit-Type
- UNKNOWN 是否被错误转换
- invalid / legacy Unit-Type 是否被错误接受
- structural contradictions 是否进入 review

> **不得让 Gate 通过另一次 LLM 推理重新「猜一个 Unit-Type」来覆盖上游语义。**

**标签**: `OWNER-INSTRUCTION`。
