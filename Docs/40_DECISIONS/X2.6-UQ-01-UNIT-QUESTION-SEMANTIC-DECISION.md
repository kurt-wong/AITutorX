## Decision 1 — Unit / Question Dimension Separation

**Recorded**:

Question and Unit are **independent dimensions**.

### Question

Represents an **answerable problem entity**.

Examples:
```text
single_choice
multiple_choice
fill_blank
calculation
proof
```

**Question-Type is NOT Unit-Type.**

### Unit

Represents **structural organization of Questions**.

### Canonical Unit-Type

**ONLY**:
```text
standalone_unit
composite_unit
```

### Forbidden canonical vocabulary

```text
standalone_question
composite_question
```

**Reason**: These names mix structural dimension and question dimension.

**Label**: `OWNER DECISION FINALIZED`

---

## Decision 2 — Composite Unit Definition

**Recorded**:

Composite Unit exists when:

### Condition A

A Question **cannot independently answer** without shared:
- material
- prerequisite condition
- contextual information

**OR**

### Condition B

Document/question structure **explicitly declares** that Questions belong together.

Examples:
- grouped examination structure
- shared reasoning training structure
- explicitly numbered sub-question group

### Important

```text
Condition A is sufficient.
Condition A is NOT necessary.
```

A question **may technically be independently answerable** but still belong to a Composite Unit due to explicit structural grouping.

**Label**: `OWNER DECISION FINALIZED`

---

## Decision 3 — Composite Evidence Preservation

**Recorded**:

System **MUST** preserve evidence explaining:

> "Why this Unit was classified as Composite."

**Do NOT store only**:
```text
LLM classified composite
```

**Store**: classification evidence.

Examples:
- shared material evidence
- dependency evidence
- explicit grouping evidence
- provenance source

**Model**:
```text
append-only evidence history
```

Historical evidence **cannot be deleted** when later decisions change.

**Label**: `OWNER DECISION FINALIZED`

---

## Decision 4 — Independent Answerability

**Recorded**:

Independent Answerability is:

> **Semantic judgment.**

**NOT**:
- regex
- deterministic keyword rules
- material existence rule

**Decision** — Use:
```text
LLM semantic analysis
+
context evidence
+
provenance
+
human review when ambiguous
```

**Forbidden**:
```text
any() style mechanical classification
```

**Label**: `OWNER DECISION FINALIZED`

**UNKNOWN MUST exist.**

# B. Design Principle

> 本节从 Owner Decision 提炼设计原则，**不**新增决策。

| Principle | Source Decision |
|-----------|-----------------|
| P1. Question-Type 与 Unit-Type 是独立维度，不得混用词面 | Decision 1 |
| P2. Canonical Unit-Type 闭集 = `{standalone_unit, composite_unit}` | Decision 1 |
| P3. Composite 判定：Condition A（依赖）充分非必要；Condition B（显式分组）独立成立 | Decision 2 |
| P4. 独立可解答 ≠ standalone；显式分组可使独立可解答的 Question 仍属 Composite | Decision 2 |
| P5. 语义结论背后必须保留 classification evidence，不只保留标签 | Decision 3 |
| P6. Evidence 模型 = append-only；后续决策不删除历史证据 | Decision 3 |
| P7. Independent Answerability = 语义判断（LLM + context + provenance + 人工复核） | Decision 4 |
| P8. 禁止 `any()` / regex / material-existence 机械分类 | Decision 4 |
| P9. UNKNOWN 是一等语义状态，表示「缺乏足够 authority/evidence」 | Decision 5 |
| P10. UNKNOWN 必须进入 review → approved classification，不得静默转换或丢弃 | Decision 5 |
| P11. Material 是语义资源，不是结构类型；standalone 与 composite 均可持有 | Decision 6 |
| P12. 语义决策 ≠ 消费行为扩展；实现未授权前保持兼容 | Decision 6 |
| P13. 迁移 = preserve legacy + introduce canonical；legacy 是证据不是权威 | Decision 7 |
| P14. 异常词（DI-01）= Preserve + Isolate + Observe；分类 NON-CANONICAL LEGACY OBSERVATION | Decision 8 |
| P15. Gate = 结构验证器，不是第二语义分类器 | Decision 9 |
| P16. 测试变更必须直接相关且保留 provenance（旧行为 / 变更原因 / 新期望） | Decision 10 |

**Authority chain（principle-level, from Decisions 4/5/9）**:
```text
semantic discovery / judgment  = LLM + evidence + human review（Decision 4）
semantic status                = ready | incomplete | unknown（Decision 5）
structural validation          = Gate（Decision 9）
UNKNOWN resolution             = review → approved classification（Decision 5）
```
